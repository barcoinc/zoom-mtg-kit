# 運用ルール

このファイルを案件フォルダの近くに置いておくと、Claude Codeがこのルールに従って動く。

**ここに書いてあるのは「初期値」です。** 自分のやり方に合わせて書き換えて構いません。
書き換えたら、以後はこのファイルの内容が優先されます。

---

## 案件フォルダの形

```
案件フォルダ/                      ← 名前は何でもいい（clients / projects / 案件 …）
├─ みどり商事様/
│  ├─ Zoomリンク.md                ← この案件のZoomリンクの唯一の保管場所
│  └─ meetings/
│     ├─ 2026-08-20_文字起こし.md   ← ① 丸ごと。要約しない。材料
│     ├─ 2026-08-20_議事録.md       ← ② そのまま送る
│     └─ 2026-08-20_自分用メモ.md   ← ③ 送らない。次の制作に効く
├─ あおぞら工房様/
└─ _未分類/                        ← 案件が決まっていないものの待避所
   └─ Zoomリンク.md                ← 録音機用の常設リンク
```

同じ日に複数回ある場合は件名で分ける（例: `2026-08-20_社内MTG午前_議事録.md`）。

> **この形は初期値です。** 案件ごとに階層を足す、`outputs/` を分ける、日付フォルダにする——
> どう変えても構いません。**削除の安全装置は案件フォルダの中を全部探すので、形を変えても働きます。**

## 案件を増やす

「〇〇さんの案件を追加して」と言われたら、**3つをまとめてやる**（1つでも欠けると後で紐づかない）。

1. `案件フォルダ/<案件名>/meetings/` を作る
2. `create-meeting` でその案件の常設Zoomリンクを発行する
3. **`案件フォルダ/<案件名>/Zoomリンク.md` に、URL・パスコード・ミーティングIDを書く**

```markdown
# みどり商事様 Zoomリンク

- URL: https://us06web.zoom.us/j/1234567890?pwd=...
- パスコード: 123456
- ミーティングID: 1234567890
```

**ミーティングIDを必ず書く。** これが録画と案件を紐づける鍵になる。
`list-recordings` が返すIDと突き合わせれば、どの案件の録画か迷わない
（会議名だけで判断すると、名前を変えた時・似た名前の案件がある時に取り違える）。

このリンクは**日時に関係なくいつでも使える**し、設定した時間で強制終了もしない。
「毎週〇曜18:00」という枠は名目なので、実際の開催日時と違っていて構わない。

## 打ち合わせ1回から3つ作る

| | 置き場所 | 性質 |
|---|---|---|
| **① 文字起こし（丸ごと）** | `meetings/` | **要約しない。材料。**「あの人の言い回しで」の引き出し元 |
| **② 議事録** | `meetings/` | **そのまま送る** |
| **③ 自分用メモ** | `meetings/` | **送らない。次の制作に一番効く** |

**議事録＝そのまま送るもの**なので、送付用という別ファイルは作らない。
内部向けの見立て・人物評・未確定数値は、議事録ではなく**③ 自分用メモ**に書く。

### 見せ方（順番が大事）

一度に3つ出すと混乱する。**送るものを先に、メモは「あるよ」と伝えるだけ。**

1. 『議事録ができました。**これをそのまま送れます。**』→ ②の本文を出す
2. 『あわせて、あなた用のメモも残しました。相手の言い回しや、どこで乗り気になったかを書いてあります。**これは送らないでください。**』→ 本文は頼まれない限り広げない
3. 『打ち合わせの文字起こしも、まるごと残してあります』の一言だけ。中身は出さない

## ② 議事録の型

```markdown
# 〇〇 議事録（YYYY年M月D日）

・日時：YYYY年M月D日（曜）HH:MM〜HH:MM（NN分）
・ご出席：氏名様／氏名様／弊社 氏名

■ 本日決まったこと

■ 弊社で対応すること
　・タスク（期限）

■ 貴社にご対応いただくこと
　・タスク（期限）

■ その他
　・今後につながる話／今後決めたいこと

■ 打ち合わせの流れ
　（全体の流れ。読めば何を話したか分かる）

■ 補足
　・文字起こしの精度に関する注意（固有名詞・金額の誤認識など）
　・確定できなかった数値
```

- **「こちら」と「相手」は必ず分ける**（担当が曖昧なままだと後で揉める）。期限が出ていなければ（期限なし）と書く
- 「その他」には、決まってはいないが今後につながる話・今後決めたいことを入れる
- 「打ち合わせの流れ」には**なぜその結論になったか**を残す。決まったことだけ並べても半年後に再現できない。ただし人物評はここにも書かない
- 発言の引用は入れない。言い回しが要る時は、残っている文字起こしから取り出せばよい
- **社内MTGのとき**は「弊社／貴社」の区別が無いので、「■ 対応すること」の下に担当者別の見出しを立て、冒頭に「※社内MTGのため担当者別に記載」と入れる

### 相手の呼び方

議事録は**そのまま先方に送る書類**なので、呼称を間違えたまま出さない。

- 案件名が**法人**（株式会社・合同会社・〜社 など）→ 『弊社』『貴社』
- 案件名が**個人名**→ 『当方』『〈お名前〉様』（例：山田様にご対応いただくこと）
- 迷う時だけ、**初めて議事録を出した直後に1回だけ**聞く：『この呼び方でよろしいですか？（貴社／〈お名前〉様）』
- 決まったら、このファイルの型に呼称ごと書き足して、**二度と聞かない**

### 議事録に書かないもの

そのまま送る書類なので、以下は入れない（③のメモへ回す）。

- 相手／第三者の健康状態・家庭の事情・金銭事情
- 人物評（「〇〇さんが電話していなかった」等）
- 社内の見立て・仮説（「本当は〇〇を狙っているのでは」等）
- 精度が確定していない数値（要確認のまま外に出さない。■ 補足 に「未確定」と書く）
- 未決事項を決定のように書くこと

## ③ 自分用メモの型

```markdown
■ 自分用メモ（送るものではありません）

【次の仕事に効く確定事項】
　・期限・予算・体制・禁止事項など、次に動くときの制約になるもの

【相手の言い回し】
　・（相手が使った生の言葉をそのまま。要約しない。口調・語彙・比喩は加工した瞬間に死ぬ）

【相手の反応】
　・どこで乗り気になったか／どこで渋ったか

【こだわり・避けたいこと】
　・

【こちらの見立て】
　・（例：この人は数字を出すと引く）

【数値（要確認つき）】
　・確定したもの／していないものを分ける。**確定していない数値は外に出さない**と明記する

【用語・固有名詞（要確認）】
　・自動文字起こし由来で読みが定まらないもの
```

- **議事録の要約を書かない。**②に書いたことの繰り返しは価値がゼロ。**次に何かをするときに効くもの**だけを入れる
- ここには、送ったら事故になることを書いてよい（例：『この人は決断が遅い』『予算はもっとありそう』）
- **見出しの「■ 自分用メモ（送るものではありません）」を必ず付ける**（ファイルの中にも残す）

### 誤送信を構造で防ぐ

③を誤って送ると取り返しがつかない。

- **「コピーして送れる」と言ってよいのは②だけ。**③はそう言わない・そう見せない
- ③の中身を**外に出る形**に使いそうになったら（先方へのメール文面・共有リンク・そのまま貼れる文章として渡す等）、**必ず一度止めて確認する**：『これはあなた専用のメモです。外に出す形になりますが、よろしいですか？』→ はっきり「はい」をもらうまで出さない

## 議事録化の手順

1. **`list-recordings` で対象を確認する。** ファイルサイズが全部0バイトの間はZoom側でまだ変換中。60分の会議で30〜60分かかる。**完了してから着手する。**
2. **`download-recordings` を `transcriptOnly: true` で実行する。** 議事録を作るだけならVTTで足りる。MP4は数百MBあるので落とす必要がない。
3. **どの案件の録画かを、ミーティングIDで確定する。** 各案件の `Zoomリンク.md` に書いてあるIDと突き合わせる。どれにも当たらなければ `_未分類/` へ。
4. **VTTを `vtt2md.py` で整形して、`meetings/` に置く（① 文字起こし）。**
   ```bash
   python3 workflow/vtt2md.py 入力.vtt > 案件フォルダ/<案件名>/meetings/YYYY-MM-DD_文字起こし.md
   ```
   **要約しない。丸ごと残す。**
5. **整形結果を読んで、②議事録と③自分用メモを書く。** 型は上のとおり。議事録はそのまま送るもの。内部向けの見立て・人物評・未確定数値はメモへ回す。
6. **議事録ができたら、録画を消すか必ず本人に確認する。** 勝手に消さない。消す場合は `delete-recording`（30日以内なら復元可）。

## .gitignore に必ず入れる

```
**/.env.local
```

`.env.local`（Zoomの認証情報）は必須。これが漏れると全録画にアクセスされる。

**打ち合わせの記録は、共有リポジトリに上げない。** 生ログには相手の経営状況・健康状態・家庭の事情・
社外の人物評がそのまま入っている。プライベートリポジトリなら含めてよいが、
**公開に切り替える時は必ず先に外すこと。**

## 知っておくべき挙動

### 話者が全員同じ名前になる

Zoomを録音機として使った回（対面打ち合わせ、先方主催MTGの裏で自分の部屋を開いておく等）は、
音声入力が1系統しかないため**全発話が自分の名義**になる。

これは壊れているのではない。`vtt2md.py` が自動判定して、話者ラベルを外したログ形式で出力する。
**誰の発言かは文脈から判断して議事録を書く。** 議事録の補足に「話者判定が効いていない」と明記する。

### 文字起こしの精度

自動文字起こしは**固有名詞をほぼ確実に間違える**。人名・社名・サービス名は要確認扱いにし、
議事録の補足に「〇〇は表記ゆれあり、要確認」と書く。**勝手に推測で直さない。**

対面録音（カフェ等）は環境音でさらに精度が落ちる。**精度がどうしても要る回は、スマホのボイスメモでも
同時に録っておく**と保険になる（Zoomの自動文字起こしより、あとから起こし直した方が精度は上がる）。
※ 起こし直す道具はこのキットには入っていない。

### 配布URLの事故

ブラウザのアドレスバーからコピーすると `.../macros/u/4/...` のような**アカウント指定が混ざる**ことがある。
これが付いていると**他の人が開けない**（404になる）。配る前に `/u/N/` が無いか必ず確認する。
