# 運用ルール

このファイルを案件フォルダの近くに置いておくと、Claude Codeがこのルールに従って動く。

---

## フォルダ構成

```
clients/
├─ <案件名>/
│  ├─ context/
│  │  ├─ 10_zoom-mtg-link.md          ← この案件のZoomリンクの唯一の保管場所
│  │  ├─ 260805_〇〇_文字起こし.md     ← ① 丸ごと。要約しない。材料
│  │  └─ 260805_学習メモ_〇〇.md       ← ③ 送らない。次の制作に効く
│  └─ outputs/
│     └─ 260805_議事録_〇〇.md         ← ② そのまま送る
└─ _未分類/                            ← 案件が決まっていないものの待避所
   └─ context/10_zoom-mtg-link.md      ← 録音機用の常設リンク
```

### 打ち合わせ1回から3つ作る（2026-08-10 確定）

| | 置き場所 | 性質 |
|---|---|---|
| **① 文字起こし（丸ごと）** | `context/` | **要約しない。材料。**「あの人の言い回しで」の引き出し元 |
| **② 議事録** | `outputs/` | **そのまま送る** |
| **③ AI学習用メモ** | `context/` | **送らない。次の制作に一番効く** |

**議事録＝そのまま送るもの**なので、送付用という別ファイルは作らない。
内部向けの見立て・人物評・未確定数値は、議事録ではなく**③ 学習メモ**に書く。

### 命名

```
context/YYMMDD_<件名>_文字起こし.md
outputs/YYMMDD_議事録_<件名>.md
context/YYMMDD_学習メモ_<件名>.md
```

同じ日に複数回ある場合は件名で分ける（例: `260807_社内MTG午前_文字起こし.md`）。

### 型

`議事録テンプレート.md` を参照。議事録は次の5ブロック。

```
■ 本日決まったこと
■ 弊社で対応すること        ・タスク（期限）
■ 貴社にご対応いただくこと   ・タスク（期限）
■ その他
■ 打ち合わせの流れ
```

社内MTGは「弊社／貴社」の区別がないので、**■ 対応すること**の下を担当者別にする。

### `_未分類` の使い方

対面打ち合わせの録音、先方主催MTGの自分側での録画、案件が決まっていない初回接触はここに入れる。
**あとから案件が確定したら、そのクライアントの `meetings/` へ移す。** ここは恒久的な置き場ではなく待避所。

---

## .gitignore に必ず入れる

```
clients/*/meetings/
**/.env.local
```

`.env.local`（Zoomの認証情報）は必須。これが漏れると全録画にアクセスされる。

**文字起こし・学習メモは除外しない（2026-08-10 確定）。** リポジトリがプライベートなので、
そのまま入れてよい。ただし**リポジトリを公開に切り替える時は、必ず先にこれらを外すこと。**
打ち合わせの生ログには相手の経営状況・健康状態・家庭の事情・社外の人物評がそのまま入っている。

## 母艦DBにも保存する

ローカルに置くだけでなく、AIマロンのクラウドDBにも入れる（他案件の制作で `recommend` / `compose_pack` が引けるようになる）。

- **② 議事録** → `save_output(customer, type="議事録", title, body)`
- **③ 学習メモ** → `save_customer(customer, subtype="context", title, body)`
- **① 文字起こし** → `save_customer(customer, subtype="context", title, body)`

## 議事録化の手順

1. **`list-recordings` で対象を確認する。** ファイルサイズが全部0バイトの間はZoom側でまだ変換中。60分の会議で30〜60分かかる。**完了してから着手する。**
2. **`download-recordings` を `transcriptOnly: true` で実行する。** 議事録を作るだけならVTTで足りる。MP4は数百MBあるので落とす必要がない。
3. **VTTを `vtt2md.py` で整形して、`context/` に置く（① 文字起こし）。**
   ```bash
   python3 vtt2md.py 入力.vtt > clients/<案件名>/context/YYMMDD_<件名>_文字起こし.md
   ```
   **要約しない。丸ごと残す。**
4. **整形結果を読んで、②議事録（`outputs/`）と③学習メモ（`context/`）を書く。** 型は `議事録テンプレート.md` に従う。
   議事録はそのまま送るもの。内部向けの見立て・人物評・未確定数値は学習メモへ回す。
5. **議事録ができたら、録画を消すか必ず本人に確認する。** 勝手に消さない。消す場合は `delete-recording`（30日以内なら復元可）。

## 知っておくべき挙動

### 話者が全員同じ名前になる

Zoomを録音機として使った回（対面打ち合わせ、先方主催MTGの裏で自分の部屋を開いておく等）は、
音声入力が1系統しかないため**全発話が自分の名義**になる。

これは壊れているのではない。`vtt2md.py` が自動判定して、話者ラベルを外したログ形式で出力する。
**誰の発言かは文脈から判断して議事録を書く。** 議事録の補足に「話者判定が効いていない」と明記する。

### 文字起こしの精度

自動文字起こしは**固有名詞をほぼ確実に間違える**。人名・社名・サービス名は要確認扱いにし、
議事録の補足に「〇〇は表記ゆれあり、要確認」と書く。**勝手に推測で直さない。**

対面録音（カフェ等）は環境音でさらに精度が落ちる。**精度が要る回は、スマホのボイスメモで録って
ローカルのWhisper large-v3 にかける方が確実。** Zoomの自動文字起こしより明確に上。

### 配布URLの事故

ブラウザのアドレスバーからコピーすると `.../macros/u/4/...` のような**アカウント指定が混ざる**ことがある。
これが付いていると**他の人が開けない**（404になる）。配る前に `/u/N/` が無いか必ず確認する。

### 定期枠は名目

`create-meeting` で作ったリンクは「毎週〇曜18:00」という枠を持つが、
**URLは日時に関係なくいつでも使える**し、設定した時間で強制終了もしない。
実際の開催日時と枠が違っていても問題ない。
